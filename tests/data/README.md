## pattern_*.mp4 layout

Generated by `tools/gen_test_media` (Release build): `gen_test_media --all tests/data`.

- H.264 High, BT.709 limited range, 60/1 fps CFR, GOP 2 s, no B-frames, VBR (1080p: 6 Mbps mean / 9 Mbps peak,
  4K: 14 / 21 Mbps; the synthetic content needs far less, so the files are ~0.5 Mbps). 1080p: 300 frames, 5.0 s;
  4K: 180 frames, 3.0 s. Frame n has presentation time `FrameTimeUs(n, 60, 1)` (0, 16666, 33333, ...).
- Tracks in file order: 1 video, 2 AAC-LC 48 kHz stereo 192 kbps. (The MF source reader lists the tracks in reverse
  order: reader stream 0 is the audio; see DECISIONS.md P04 4.2.)
- Picture: 8 vertical bars (75 % white, yellow, cyan, green, magenta, red, blue, black; each width/8 px) scrolling right
  by 4 px per frame. Every frame with `n % 60 == 0` is a **flash**: the whole picture is white (255) except the counter box.
- Frame counter: black box `(32,32)-(432,96)` (x0,y0)-(x1,y1) exclusive; the frame number n as 12 decimal digits, most
  significant first, white seven-segment glyphs. Digit d (0..11) occupies the cell with top-left `x0 = 34 + 33*d`,
  `y0 = 36`, 28 x 56 px, 4 px strokes. Segment rectangles relative to the cell (left, top, right, bottom exclusive):
  a `(4,0,24,4)`, b `(24,4,28,26)`, c `(24,30,28,52)`, d `(4,52,24,56)`, e `(0,30,4,52)`, f `(0,4,4,26)`, g `(4,26,24,30)`.
  Read a digit by sampling luma > 128 at the segment centres a `(14,2)`, b `(26,15)`, c `(26,41)`, d `(14,54)`,
  e `(2,41)`, f `(2,15)`, g `(14,28)`; segment masks (bit 0 = a ... bit 6 = g) for 0-9:
  `3F 06 5B 4F 66 6D 7D 07 7F 6F`. Reference reader: `tests/media/test_data_test.cpp` (`ReadCounter`).
- Audio: 1 kHz sine at -12 dBFS (both channels); for 20 ms (960 frames) starting at each flash frame's time
  (t = 0, 1, 2, ... s) the sine is 2 kHz instead (the "beep", phase-continuous). Decoded audio starts at t = 0.

Regenerate only on the reference machine; the decoder/playback tests assume these exact frame counts and timestamps.
